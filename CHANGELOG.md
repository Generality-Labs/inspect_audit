## [Unreleased]

### Added

- Epoch defect classes on item labels: a question- or grading-labels DEFECT names `epoch_class` (`impossible_as_written`, `false_negative`, `false_positive`; grading-labels takes only the last two) and a `sub_reason` from that class's list (`_labels.SUB_REASONS`), required on new verdicts; an auditor's review can set or correct them. `defect_types` stays, optional, and older findings are read through a fixed mapping (`LEGACY_CLASSES`). The Epoch page groups the representative errors by class in Epoch's order with counts, prints each row's sub-reason, gives the counts per class in the scoring row's notes, and writes `classes.json`. The sampling text now says every task is assessed when a benchmark has at most 50 (Epoch's rule), not 100.
- The `epoch` publisher: an Epoch AI benchmark review page generated from the frozen findings. The rubric (checks, scales, the 20% scoring threshold, the verdict rule, the page's blocks and limits) is one description, `audit/epoch.json`; the auditor rates its rows in `auditor.ratings` under the `epoch-review` skill, in two phases within one audit (the task audit, blind to logs, which is all an audit without logs does and can only end Flawed or Incomplete; then, when logs were supplied, the log-dependent rows in the same run), and the verdict, the defect rate from the sample labels and the rubric tables are derived at submission and publication, never written. `Rating` gains optional `fields`, `impact` and `override` for the rows that need them; the register's subject records the logs the audit was given; a publisher may bring audit-time skills and stage its description into the workspace.
- The `grading-labels` check, phase 2's counterpart to question-labels: one investigator per item with the logs, labelling each recorded grade a false negative, false positive or grader failure, with a headline for the page. An item defective under either check counts once in the Epoch scoring row.
- `inspect-audit-epoch-review`: renders the Epoch page again from what an audit saved (a `hawk download-artifacts` folder, a findings bundle, a findings.json or the audit's eval log, with the auditor's prose.json), after a renderer fix or when the pod kept nothing, without a model or a box.
- Two smoke cases for the Epoch review: `epoch-simpleqa` (phase 1, no logs) and `epoch-simpleqa-logs` (both phases, with 49 of Epoch's published SimpleQA Verified runs supplied).
- Competing answers carry their sources. question-labels and grading-labels rows take `sources`, a list of `{answer, source, url, quote, key}` (at least two different answers, a public URL or exact citation, never a local copy), and an auditor's `Review` takes the same; the Epoch page prints each defective item's competing answers with their sources under the errors table, from the findings, and `sources.json` beside it. Findings without sources render as before.

### Changed

- The auditor box's benchmark probes (the register's population read) get the audit's `child_secrets` as environment, in the probe's process only, and that exec records no transcript event, so the values are never logged. A gated dataset (HLE's cais/hle, HF_TOKEN) could not be read for the register before: only child jobs received the secrets.
- The `runner` extra declares `joserfc`. Hawk 4.2's `hawk.cli.download`, which fetches `hawk:` logs on a runner, now imports `hawk.cli.util.auth` and through it `joserfc`, which only `hawk[cli]` declares, so an audit given `hawk:` logs failed to load with `ModuleNotFoundError: No module named 'joserfc'`.
- The Epoch page opens with the Benchmark Review Rubric and follows it directly with the representative errors (bullets, errors table, competing answers with sources), then any notice, and ends there: the template's `opening` sets the order and its `ends_after_opening` drops the summary, methodology, limitations, disclaimer and recommendations from the page. Those blocks are no longer required (one written is still checked and kept in prose.json), the publishing skill no longer asks for them, and only the footnotes the page refers to are printed. The preview also points out errors-table rows whose Notes or Affected logs share a run of six words, as a row edited into its neighbour's place.
- Supplied logs recorded by another build of the benchmark are no longer refused by the log identity check; the task name and task arguments must still match. The difference is said instead: a warning on the job, a note to every investigator and in the regrade log's metadata, `logs_provenance` on the register's subject, and a notice on the Epoch page. An Epoch review regrades Epoch's logs with a reconstruction of a private package, which the old rule made impossible. The check also resolves a task's namespace to the distribution that provides it (`bench/...` is `epoch-bench`), so a namespace that is not itself a distribution no longer reads as "not installed".
- On a Hawk runner, `artifact_dir` defaults to the job's own artifacts folder, read from the runner's infra config, so the published report and findings are fetched with `hawk download-artifacts` instead of being lost with the pod. The eval set id is Hawk's to assign, so an operator could not name the folder in the config.
- Adopted the Generality Labs [python-project-template](https://github.com/Generality-Labs/python-project-template): CI calls the shared `python-ci` workflow on Python 3.13 (so the Hawk extra installs and type-checks), the pre-commit stack (ruff lint and format, zizmor, actionlint, shellcheck, mdformat) gates commits, basedpyright replaces mypy, dev dependencies move to a `[dependency-groups]` table, and Dependabot keeps actions and Python dependencies current.
